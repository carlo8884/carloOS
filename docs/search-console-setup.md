# Google Search Console Setup — Dog.com

> Operational doc. Used during launch prep alongside [`dog-com-soft-launch-checklist.md`](./dog-com-soft-launch-checklist.md).

## Why GSC is launch-gating

Without GSC, there is no way to:
- Confirm Google has indexed pages
- See which queries surface the site
- Detect crawl errors or accidental `noindex` directives
- Get notified of manual actions or security issues

GSC verification can complete **before** DNS cutover via the DNS TXT method — verifying ownership independently of where the site is hosted.

---

## Property type — choose Domain

Two property types exist:

- **Domain property** *(preferred)*: covers `dog.com`, `www.dog.com`, and all subdomains. Verified once via DNS TXT.
- **URL prefix property**: covers only the exact URL prefix. Requires separate verification per variant (www vs apex, http vs https).

**Use Domain.** It eliminates www-vs-apex confusion and works for any future subdomain without re-verification.

---

## Verification — do this BEFORE DNS cutover

### Steps

1. Go to [search.google.com/search-console](https://search.google.com/search-console)
2. Add property → Domain → enter `dog.com` (no `https://`, no trailing slash)
3. Copy the TXT record value Google shows
4. At your domain registrar: add a TXT record on `@` (apex) with that value, TTL 300s
5. Back in GSC: click Verify

### Timing rationale

TXT-based verification is independent of A/CNAME records. Adding the TXT record while the domain still points to its old host means GSC is verified the moment you flip the A record to Vercel. Sitemap submission is then immediate.

### If verification fails

- Confirm the TXT record is on `@` (apex), not on a subdomain like `_google.dog.com`
- Wait 5 minutes (TTL 300s) and retry
- Some registrars require the value in quotes — try both

## Sitemap submission — do this AFTER DNS cutover

The sitemap URL must resolve over HTTPS, so submit after the domain points to Vercel.

1. Confirm `https://dog.com/sitemap.xml` returns 200 and contains valid XML
2. GSC → Sitemaps → enter `sitemap.xml`
3. Click Submit

The sitemap is generated by `apps/dog-com/src/app/sitemap.ts`. If routes were added recently, regenerate first:

```bash
node scripts/regenerate-sitemaps.mjs
```

GSC shows "Success" within minutes if the sitemap is well-formed. "Couldn't fetch" during the first hour is normal — wait 24h before troubleshooting.

## Performance baseline

On launch day:

- Export GSC Performance → last 7 days → CSV (it will be empty; that's the baseline)
- Screenshot the Coverage report
- Note the date — this is your Day 0

Expected trajectory:

| Day | What to expect |
|---|---|
| 3–7 | First pages appear in Coverage → Discovered |
| 7–14 | First impressions in Performance |
| 14–30 | Sustained organic impressions if content is indexable |

If no impressions by Day 14:
- Coverage → are pages marked "Excluded"? Why?
- URL Inspection on the homepage — is it indexed?
- Any unintended `noindex` directive shipped? Check `apps/dog-com/src/app/robots.ts`

## Common gotchas

| Symptom | Likely cause | Fix |
|---|---|---|
| Verification fails | TXT on wrong host (`_google.dog.com` instead of `@`) | Set TXT on `@` |
| Sitemap "Couldn't fetch" | `robots.txt` blocks Googlebot, or sitemap URL 404s | Inspect `robots.ts` and `sitemap.ts` outputs |
| Pages not indexed after 30 days | Thin content, duplicate content, or canonical issues | URL Inspection per page → check status and suggested fix |
| `www.dog.com` and `dog.com` reported separately | URL prefix property in use | Switch to Domain property |
| Sitemap shows fewer URLs than expected | Sitemap regeneration stale | Re-run `node scripts/regenerate-sitemaps.mjs` |
