## Non-blocking observations (flagged for COO triage)

### 2. Sitemap contains route-group literal `(funnels)/` ⚠ launch blocker (COO lane)

`apps/ferret-com/src/app/sitemap.ts` line 14 contains:
```
{ url: 'https://ferret.com/(funnels)/ferret-starter-kit', ... }
```

Next.js route groups (parentheses-wrapped segments) **do not appear in the URL**. The actual URL is `https://ferret.com/ferret-starter-kit`. The sitemap entry will route search engines and AI crawlers to a 404.

The sitemap is auto-generated by `scripts/regenerate-sitemaps.mjs`, so the fix is in the generator (COO lane: `scripts/*` per bot-coordination §2). Likely needs a `.replace(/\/\([^)]+\)/g, '')` in the slug pass.

**Impact:** indexing-efficiency hit + 404 in Google Search Console post-launch. Other sites with `(funnels)/` routes (dog-com, vets-co) are likely affected.

### 3. Homepage is CSS-only — no hero photo (editorial choice, not a blocker)

`apps/ferret-com/src/app/page.tsx` carries a candid comment explaining the choice — Unsplash has ~5K ferret photos but none verified yet in the CarloOS Unsplash catalog, and cross-site photo reuse violates visual differentiation. The current hero leans on typography + gradient and reads "indie hobbyist magazine," matching the brand brief.

This is editorially honest and within Visual lane discretion. **Not a launch blocker.** Recommendation: Carlo picks 1-2 ferret hero IDs from Unsplash in his next browsing pass; Visual Bot wires them via `scripts/image-queries.json` (PR #223 pattern) and the `<StockImage>` component. Until then, CSS-only is the right call.
