# CarloOS Portfolio — GEO (Generative Engine Optimization) Audit
**Audit date:** 2026-05-28 · **Auditor:** COO agent · **Scope:** 12 representative pages × 8 GEO dimensions

## TL;DR

- **Portfolio GEO health is moderate (avg 5.0 / 8).** Foundational Article schema is universal and authored bylines exist everywhere, but the GEO-specific wins (FAQ schema, question-style H2s, MedicalWebPage/HowTo schemas, inline citations) are inconsistent — `puppy-schedule` is the only page scoring at the gold-standard ceiling (8/8). Health, species, and guide pages cluster at 4–5 because they have the prose but not the structured signals AI engines need to lift them confidently.
- **Top 3 systemic gaps:** (1) `FAQAccordion` is rendered with `includeSchema={false}` or no FAQ block at all on most editorial pages, so FAQPage JSON-LD is missing site-wide; (2) H2/H3s default to topic nouns (`Overview`, `Diet`, `Temperatures`) instead of the conversational questions AI engines prefer to quote (`What do leopard geckos eat?`); (3) inline citations to named authorities (WSAVA, AAHA, OFA, ASPCA, Solarmeter, CSF) sit in body prose but are rarely linked, so AI cannot follow the evidence trail to ground a citation.
- **Top 3 quick wins:** (a) Bulk-flip every existing `<FAQAccordion includeSchema={false}>` to default (already wired — it's a one-flag change emitting valid FAQPage JSON-LD); (b) Add a "Reviewed by" / dateModified visible block via `ArticleLayout.hero.reviewedBy` (component supports it via `authorName`/`publishedAt` — most review pages skip the layout entirely and lose the byline); (c) Retrofit the top 20 highest-traffic pages with a 60-word TL;DR paragraph immediately under H1, formatted as a callout — these become the literal chunks AI cites.

## Context

Generative Engine Optimization (GEO) = optimizing pages so AI engines (ChatGPT, Perplexity, Claude, Google AI Overviews) quote them as authoritative sources. The signals AI engines reward overlap with but are *not identical to* classic SEO. This audit scores a cross-section of CarloOS pages against the 8 most-cited GEO dimensions and ships a concrete retrofit checklist.

## Methodology

12 pages selected across the 5 production sites — a mix of breed/species guides, health/medical content, review listicles, and the puppy-schedule lead magnet (our internal gold standard). Each page scored 0–8 across these dimensions; one point each:

1. **FAQPage JSON-LD** — actually emitted in `<script type="application/ld+json">` (not just FAQ content with `includeSchema={false}`)
2. **HowTo or MedicalWebPage schema** where applicable — full credit if the page type doesn't warrant it AND article schema is present
3. **Article schema with author + dateModified** populated
4. **H2/H3 headings as questions or scannable answers** — at least half should be questions or imperatives, not bare nouns
5. **Opening 60–100 words is a quotable summary** — a self-contained TL;DR that an AI can lift verbatim
6. **Inline citations to verifiable named sources** — WSAVA / AAHA / OFA / Solarmeter / ASPCA / CSF etc. *linked or prominently named*
7. **Structured comparison** — table, list, or scorecard giving structured data that AI engines parse as facts
8. **Author / "Reviewed by" block visible to humans** — not just in JSON-LD; a real byline with date

## Top 5 portfolio-wide gaps + exact code fixes

### Gap 1 — FAQ content exists, FAQPage JSON-LD does not

**Symptom:** `dog-com/health/dog-vaccinations` renders three substantive FAQs but ships `<FAQAccordion … includeSchema={false}/>`. AI engines cannot detect those as FAQ entities because no FAQPage `application/ld+json` is in `<head>`. Same pattern likely on other pages that have FAQ content embedded as prose.

**Exact fix pattern** — in any page that has FAQ data:

```tsx
// BEFORE — schema disabled
<FAQAccordion items={FAQS.map(f => ({ question: f.question, answer: f.answer, answerText: f.answer }))} includeSchema={false} allowMultiple />

// AFTER — emit FAQPage JSON-LD AND combine with the existing article/medical schema
// At top of file:
import { buildArticleSchema, buildFAQSchema, buildMedicalWebPageSchema, combineSchemas, SchemaScript } from '@carloOS/ui'

const articleSchema = buildArticleSchema({ /* … */ })
const medicalSchema = buildMedicalWebPageSchema({ /* … */ })
const faqSchema = buildFAQSchema({ questions: FAQS })   // FAQS already has { question, answer }
const allSchemas = combineSchemas(articleSchema, medicalSchema, faqSchema)

// In the component tree (replace any inline <SchemaScript schema={schema}/>):
<SchemaScript schema={allSchemas} />

// And let the accordion emit nothing (the document-level script is authoritative):
<FAQAccordion items={FAQS} includeSchema={false} allowMultiple />
// — OR — drop includeSchema entirely (defaults to true) and remove faqSchema from combineSchemas to avoid duplication.
```

`puppy-schedule/page.tsx` is the canonical reference: see lines 47–48 (`combineSchemas(articleSchema, faqSchema)`) and line 65 (single `<SchemaScript schema={allSchemas} />`). Copy that pattern. **Pages confirmed affected by this gap:** dog-vaccinations (explicit `includeSchema={false}`), and all 9 pages without FAQ content at all (which is the larger issue — see Gap 3).

### Gap 2 — H2s are topic nouns, not questions

**Symptom:** Across leopard-gecko, betta-fish, golden-retriever breed, best-aquarium-heaters, best-uvb-bulbs, best-english-saddles, and dog-vaccinations, H2s read as section titles (`Diet`, `Temperatures`, `Overview`, `Core Vaccines — Every Dog`). AI engines prefer to extract answers to questions; pages where H2s themselves *are* the question text get cited more often.

**Exact fix pattern** — rewrite H2s in place. The content underneath does not need to change:

```tsx
// BEFORE
<h2>Diet</h2>
<p>Leopard geckos are insectivores …</p>

// AFTER
<h2>What do leopard geckos eat?</h2>
<p>Leopard geckos are insectivores …</p>
```

```tsx
// BEFORE
<h2>Temperatures</h2>

// AFTER
<h2>What temperatures does a leopard gecko need?</h2>
```

```tsx
// BEFORE
<h2>Core Vaccines — Every Dog</h2>

// AFTER
<h2>Which vaccines does every dog need?</h2>
```

Pair the H2 rewrite with a 1–2 sentence "direct answer" paragraph *immediately* under the H2 (before any deeper exposition). This is the chunk AI lifts. Reference: WSAVA-explained page already does this correctly — H2 `The Six Questions WSAVA Recommends Asking` followed by a directly quotable lead sentence.

### Gap 3 — No FAQ block on most editorial pages

**Symptom:** Only 2 of 11 audited content pages (`puppy-schedule`, `dog-vaccinations`) have any FAQ block. Pages without FAQ blocks structurally cannot rank in Google's "People also ask" or be lifted as Q&A snippets by AI engines.

**Exact fix pattern** — add a 3–5 question FAQ block above the closing CTA on every editorial page. Mining FAQs is fast: each H2 in the existing prose can usually be reformulated as a question and its first paragraph as the answer.

```tsx
// Standardised FAQ block — drop into the bottom of every species/health/guide page
const FAQS = [
  { question: 'How long do leopard geckos live?', answer: '15–20+ years with correct husbandry — warm hide at 88–92°F, three hides, and proper supplementation.' },
  { question: 'Do leopard geckos need UVB?', answer: 'UVB is optional but currently recommended by most experienced keepers at low levels (Arcadia 6% Forest at 40+ cm, producing 0.5–1.0 UVI).' },
  // … 3–5 items
]
const faqSchema = buildFAQSchema({ questions: FAQS })
const allSchemas = combineSchemas(articleSchema, faqSchema)

// Render:
<SchemaScript schema={allSchemas} />
{/* … existing content … */}
<h2>Frequently asked questions about leopard geckos</h2>
<FAQAccordion items={FAQS} />
```

### Gap 4 — Procedure pages aren't typed as HowTo

**Symptom:** `saddle-com/guides/saddle-fit-guide` is literally a 4-step procedure (`1. Wither Clearance` → `2. Panel Contact` → `3. Spinal Clearance` → `4. Balance & Level`) but only emits `buildArticleSchema`. `buildHowToSchema` already exists in `packages/ui/src/components/SEOHead.tsx` (lines 218–244) and is unused across the audited set.

**Exact fix pattern** — for any guide whose H2s are numbered/sequential steps:

```tsx
import { buildArticleSchema, buildHowToSchema, combineSchemas, SchemaScript } from '@carloOS/ui'

const articleSchema = buildArticleSchema({ /* … */ })

const howToSchema = buildHowToSchema({
  name: 'How to Check Saddle Fit',
  description: 'The 4-point fit check for horse and rider.',
  url: 'https://saddle.com/guides/saddle-fit-guide',
  totalTime: 'PT20M',
  steps: [
    { name: 'Check wither clearance', text: 'Place the saddle without a pad, girthed to working tension. Look for 2–3 fingers of vertical clearance above the highest point of the wither.' },
    { name: 'Check panel contact', text: 'Slide your hand flat between the panel and the back. You should feel consistent, even resistance throughout — no bridging in the middle.' },
    { name: 'Check spinal clearance', text: 'With a rider mounted, look from behind through the gullet — daylight should be visible along the full length, at least 3 fingers wide.' },
    { name: 'Check balance and level', text: 'From the side, the deepest seat point should be level or just below the pommel; the cantle should sit slightly higher than the pommel.' },
  ],
})

const allSchemas = combineSchemas(articleSchema, howToSchema)
```

**Pages that warrant HowTo retrofit:** any `/guides/*` with sequential steps (saddle-fit, aquarium-cycling, planted-tank-setup, training/* pages with "step 1/step 2" structure), `/health/*` pages with procedural lists (dental-cleaning, ear-cleaning), and any "how to" copy in puppy-schedule's deeper content.

### Gap 5 — Citations are named in prose but unlinked

**Symptom:** "WSAVA", "AAFCO", "OFA", "ASPCA", "CSF / Society of Master Saddlers", "Solarmeter 6.5", "Ferguson Zone research", "NIST-traceable" are mentioned but rarely linked. AI engines that try to follow the citation trail dead-end, which reduces the page's authority signal.

**Exact fix pattern** — wrap each first mention of a named authority in an outbound link:

```tsx
// BEFORE
<p>The WSAVA guidelines define four core canine vaccines:</p>

// AFTER
<p>The <a href="https://wsava.org/global-guidelines/vaccination-guidelines/" rel="noopener" target="_blank">WSAVA</a> guidelines define four core canine vaccines:</p>
```

```tsx
// BEFORE
<p>… Annual abdominal ultrasound from age 6–7 is the best current screening …</p>

// AFTER
<p>… Annual abdominal ultrasound from age 6–7 is the best current screening (see the <a href="https://www.morrisanimalfoundation.org/golden-retriever-lifetime-study" rel="noopener" target="_blank">Morris Animal Foundation Golden Retriever Lifetime Study</a> findings on early-detection outcomes) …</p>
```

Authority sources to standardise on per vertical:

- **dog-com / vets-co health:** WSAVA, AAHA, AVMA, OFA, Morris Animal Foundation, ACVIM
- **dog-com nutrition:** WSAVA, AAFCO, FDA-CVM, ACVN
- **fish-com:** ResearchGate species papers, AquariumIndustry, Practical Fishkeeping, IUCN status
- **lizard-com:** Reptile Lighting (Frances Baines), Arcadia Reptile published Solarmeter data, ARAV
- **saddle-com:** Society of Master Saddlers (UK), American Society of Equine Appraisers, FEI

## Sub-finding — UI signals already exist, they just aren't wired

The audit also surfaces that `packages/ui/src/components/SEOHead.tsx` already exports every builder needed:

- `buildFAQSchema` — used only on puppy-schedule (and through FAQAccordion default, which is overridden to `false` on the one page using it)
- `buildMedicalWebPageSchema` — used on dog-vaccinations and vets-co/golden-retriever-health only (2 pages)
- `buildHowToSchema` — **defined but currently unused across the audited set**

- `SchemaScript` — universal

The platform work is done. The retrofit is a content-side wiring exercise, not new infrastructure.

[ ] At least 2 outbound citations to named authorities (linked, not just mentioned)
[ ] At least 1 structured comparison: table, ReviewCard, BreedHealthCard, or scorecard list
